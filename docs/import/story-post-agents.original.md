# Story Post 개발 원칙

- 이 프로젝트는 캠툴과 독립된 모바일 게임이다. 캠툴의 웹 구조·출시 기준을 복사하지 않는다.
- 작업 전 README와 관련 docs를 읽고 Git 상태를 확인한다.
- 권장 스택은 React Native + Expo + TypeScript strict + pnpm이다. 실제 설치 시 안정 버전과 호환성을 확인하고 lockfile로 고정한다.
- 이야기 데이터, 순수 진행 엔진, 화면 연출, 저장소를 분리한다.
- 작품별 분기를 UI에 하드코딩하지 않는다. 안정적인 작품·노드·선택지 ID를 사용한다.
- 초기 콘텐츠는 한국어로 작성한다. 번역 가능하도록 ID와 본문을 분리할 수 있는 구조를 유지하되 영어 동시 출시는 현재 범위가 아니다.
- 초기 플레이는 오프라인·로그인 없이 제공한다. 서버, 분석, 결제, 알림은 실제 작업 범위가 될 때 추가한다.
- 진행 저장은 선택 결과와 다음 노드를 원자적으로 반영한다. 데이터/콘텐츠 버전 변경 시 기존 저장 호환을 검토한다.
- 콘텐츠 및 에셋의 출처·이용 권리를 기록한다. 비밀값과 서명 키를 커밋하지 않는다.
- 구현 시 타입 검사·린트·진행 엔진/저장 테스트를 실행한다. UI는 iOS와 Android에서 글자 확대·작은 화면·이어하기를 검증한다.
- 문서 준비와 실제 앱 실행/검증 완료를 구분해 보고한다.
- 커밋 시 의도별로 분리하고 staged diff를 검토한다. 형식은 <type>(<scope>): <summary>를 사용한다.
