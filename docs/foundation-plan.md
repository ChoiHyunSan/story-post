## 구현 구조

app/은 Expo Router 진입점, src/features/reader는 모바일 화면이다.
src/engine은 React/SQLite에 의존하지 않는 순수 규칙이며 src/storage는 migration과 저장소다.
src/content는 버전별 콘텐츠 조회, scripts/는 원고/SQL 관리, src/generated는 생성 코드다.

모든 읽기/쓰기는 전용 연결의 직렬 큐를 통과한다. BEGIN IMMEDIATE와 commit/rollback을
같은 연결에서 처리해 비동기 쿼리가 다른 트랜잭션에 섞이지 않도록 한다.
UI는 저장 완료 후 화면을 갱신한다. 플레이어 앱에는 네트워크·계정·광고·AI API가 없다. 별도 로컬
제작실만 작가의 명시적 요청으로 OpenAI API를 호출할 수 있고, 키와 결과는 앱 번들에 포함하지 않는다.

## 다음 작업

1. 양 플랫폼 실제 기기와 VoiceOver/TalkBack 음성 탐색 검증을 완료한다.
2. 제작실의 v4 draft를 플레이테스트해 선택의 명확성·실제 소요 시간·분위기를 조정한다.
3. 사람의 플레이테스트 결과로 다음 퇴고를 진행한 뒤 아트/음향을 단계별로 연결한다.

스토어 서명·배포, 결제, 원격 CMS, 클라우드 저장은 현재 구현 범위가 아니다.

제작실 원고의 선택지에는 조건·효과 폼과 한국어 상태 의미를 제공한다. 규칙 사본을 전체 분기
검사한 뒤 적용하고 저장은 별도로 수행한다. 후속 편집 전에는1단계 구조 취소가 가능하다.

복제 게시·목록 갱신·원고 열기는 독립된 실패 단계로 안내한다. 원고 조회 실패는 현재 편집을
보존하고 작품 목록의 ‘원고 다시 열기’로 복구한다. 미저장 원고 교체에는 확인을 요구한다.
