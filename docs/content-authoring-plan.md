# 콘텐츠 제작 원장 설계

## 목적

작가·기획자·연출자가 스토리, 선택, 이미지, BGM, 효과음과 표시 시점을 코드나 큰 JSON 파일을
직접 수정하지 않고 관리하는 구조를 정의한다. 제작 원장은 편집하기 쉬운 테이블이고, 모바일 앱은
승인된 원장을 빌드한 불변 콘텐츠 패키지만 읽는다.

```text
스프레드시트/로컬 제작 DB
  → 구조·권리·누락 검사
  → 분기 그래프와 연출 미리보기
  → 승인된 콘텐츠 패키지(JSON + assets manifest)
  → 앱 개발/프로덕션 번들
```

기기 SQLite의 플레이 기록과 제작 원장은 합치지 않는다. 제작용 상태나 임시 장면이 플레이어의
저장 데이터에 들어가면 안 되며, 앱은 제작 원장에 직접 접속하지 않는다.

## 제작 테이블

| 테이블 | 한 행의 의미 | 주요 필드 |
| --- | --- | --- |
| `story_work` | 편집 중인 작품 버전 | story_id, working_version, locale, schema_version, engine_contract_version, title, description, start_scene_id, status |
| `scene` | 이동 가능한 한 장면 | scene_id, ordinal, scene_type, sender, ending_id, production_status, notes |
| `content_block` | 장면 안에서 순서대로 표시할 본문 단위 | block_id, scene_id, ordinal, block_type, speaker, text |
| `choice` | 장면에서 고르는 행동 | choice_id, scene_id, ordinal, text, next_scene_id |
| `flag_definition` | 분기에서 쓰는 상태값 | flag_id, ordinal, value_type, default_value, description |
| `choice_condition` | 선택 노출 조건 | choice_id, ordinal, flag_id, operator, expected_value |
| `choice_effect` | 선택 후 상태 변화 | choice_id, ordinal, flag_id, operation, value |
| `asset` | 이미지·BGM·효과음·보이스 원장 | asset_id, asset_type, source_path, status, rights, license, hash, alt_text, duration_ms |
| `cue` | 에셋을 언제 어떻게 제어할지 정의 | cue_id, scene_id, block_id/choice_id, trigger, channel, action, asset_id, fade_ms, volume, loop |
| `release_candidate` | 검수할 고정 후보 | candidate_id, story_id, version, created_at, content_hash, asset_manifest_hash, status |

`content_block`을 두면 한 장면 안에서도 내레이션, 대사, 편지 인용, 구분선과 캡션을 순서대로
표현할 수 있다. 현재 런타임 v1은 여러 블록을 하나의 `body`로 합쳐도 되고, 이후 블록 단위 연출을
지원할 때 같은 원장을 그대로 사용한다.

## 에셋과 연출 큐

에셋 파일명이나 재생 코드를 원고 문장에 넣지 않는다. `asset`이 파일과 권리 정보를 소유하고,
`cue`가 장면의 사건과 에셋 행동을 연결한다.

### trigger

| 값 | 실행 시점 |
| --- | --- |
| `scene_enter` | 장면이 화면에 들어온 직후 |
| `before_block` | 특정 본문 블록 표시 직전 |
| `after_block` | 특정 본문 블록 표시 직후 |
| `choices_visible` | 선택지가 표시될 때 |
| `choice_selected` | 특정 선택을 확정한 직후 |
| `scene_exit` | 다음 장면으로 이동하기 직전 |

### channel과 action

| channel | 대표 action |
| --- | --- |
| `background` | show, hide, crossfade |
| `portrait` | show, hide, swap |
| `overlay` | show, hide, fade_in, fade_out |
| `bgm` | play, stop, crossfade |
| `sfx` | play, stop |
| `voice` | play, stop |

`cue`에는 `ordinal`을 두어 같은 시점의 실행 순서를 고정한다. 기본 진행은 사용자의 탭으로
넘어가며 절대 시간 타임라인을 요구하지 않는다. `duration_ms`는 일시적인 화면 효과에만 사용하고,
본문 읽기를 자동으로 넘기는 기능은 별도 승인 전까지 지원하지 않는다.

예시:

| cue_id | scene_id | trigger | channel | action | asset_id | fade_ms | loop |
| --- | --- | --- | --- | --- | --- | ---: | ---: |
| `tide-enter-bg` | `tide-road` | `scene_enter` | `background` | `crossfade` | `bg-tide-road-night` | 800 | 0 |
| `tide-enter-bgm` | `tide-road` | `scene_enter` | `bgm` | `crossfade` | `bgm-low-tide` | 1200 | 1 |
| `key-turn-sfx` | `haejin-truth` | `choice_selected` | `sfx` | `play` | `sfx-rusty-key` | 0 | 0 |

## 제작 상태

작품·장면·에셋은 다음 상태를 사용한다.

```text
draft → review → approved → released
```

- `draft`: 자유롭게 수정 가능.
- `review`: 분기·문구·에셋과 권리 정보를 검수 중.
- `approved`: 빌드 후보. 누락 에셋과 검증 오류가 없어야 한다.
- `released`: hash가 잠긴 불변 버전. 수정은 다음 working_version에서 한다.

에셋은 파일이 없어도 `planned` 상태로 먼저 등록할 수 있다. `approved` 후보에서는 사용되는 모든
에셋이 `ready` 또는 `approved`이고 source_path, 권리 보유자·라이선스와 hash가 있어야 한다.

## 편집 화면과 파일 형식

첫 단계는 별도 서버보다 스프레드시트와 로컬 제작 DB가 적합하다. 표 하나를 억지로 넓히지 않고
위 테이블마다 시트를 둔다. CSV import/export를 제공하고 긴 본문은 셀 안의 줄바꿈을 보존한다.

작가에게는 다음 결합 뷰를 제공한다.

- 원고 뷰: scene 순서로 본문 블록과 선택을 이어서 표시.
- 분기 뷰: scene과 choice 연결, 조건과 엔딩 도달 여부 표시.
- 연출 시트: 장면별 이미지·BGM·SFX cue를 시간 순서로 표시.
- 에셋 현황: planned/missing/ready/approved와 권리 정보 필터.
- 릴리스 검사: 도달 불가 장면, 막힌 선택, 누락 에셋, 중복 cue와 이전 버전 변경 표시.

## 빌드 결과

제작 원장은 다음 두 결과를 만든다.

1. `story.json`: 진행 엔진이 읽는 장면·선택·조건·효과·엔딩.
2. `assets.json`: 에셋 ID, 번들 경로, hash와 cue 목록.

두 파일과 실제 에셋 목록을 함께 hash하여 릴리스 후보를 만든다. 현재 `releases.lock.json`의 원고
불변 검사는 콘텐츠 패키지 전체 잠금으로 확장한다. 개발 전용 원고·에셋은 계속 `__DEV__`에서만
포함하고 프로덕션 번들 검사를 유지한다.

   승인 권한이 실제로 필요해질 때 이 계약을 유지한 채 CMS를 검토한다.

## 작업본 검증 경계 — 2026-10-01

draft는 파일이 없는 `planned` 에셋과 cue를 저장할 수 있다. 원장에는 계획을 남기고 런타임 미리보기에는
해당 에셋과 참조 cue를 제외한다. 미완성 항목도 ID·경로·channel/action·대상 장면·실행 순서는 검증한다.
review/approved/released는 참조 에셋이 ready/approved여야 한다. 완성 에셋의 실제 파일 SHA-256,
권리 보유자와 라이선스를 export 시 검사한다. 본문 cue의 block도 해당 장면 소유인지 확인한다.

브라우저는 AI 제안을 복사본에서 검증한 뒤 교체하며, 다른 장면의 본문·선택지 ID를 덮어쓰거나 없는
다음 장면에 연결할 수 없다. 기존 조건·효과·순서는 유지한다. 이미지/사운드 적용 로직은 동일 순수 함수를
사용한다. block/choice 대상이 필요한 AI 연출 제안은 자동 적용하지 않고 연출 편집기에서 연결한다.
저장 시점 스냅샷 뒤의 수정은 미저장으로 유지하고 중복 저장 요청을 차단한다.

## 저장 충돌과 비동기 편집 보호

GET 원장은 CSV 내용으로 계산한 `revision`을 반환하고 PUT은 같은 `expectedRevision`을 요구한다.
다른 탭이나 외부 CSV 편집으로 내용이 바뀌면 409로 거부하고 현재 편집 내용은 브라우저에 유지한다.
동시 편집 병합은 하지 않는다. 변경을 별도로 보관한 뒤 최신 원고를 열어 반영한다.

파일 저장은 10개 CSV를 작업 디렉터리 사본에서 만든 뒤 디렉터리를 교체한다. 교체 실패 시 원본을
복원하고, 복원마저 실패하면 원본 backup 경로를 남긴다. 프로세스 강제 종료에 대한 자동 복구는 아직
포함하지 않으므로 SQLite 트랜잭션과 동일한 내구성을 주장하지 않는다.
브라우저와 Node가 `session.mjs`의 같은 편집 계약을 사용한다. 늦은 저장·불러오기, 수정 중 응답,
중복 저장과 실패 후 재시도는 지연 Promise로 검증한다. 미저장 변경이 있으면 복제 전에 저장을 요구한다.

## 플레이 미리보기

제작실의 플레이 미리보기는 현재 편집 원장을 검증한 스냅샷을 사용한다. 서버에서 모바일 앱과 같은
순수 엔진으로 선택 ID 경로를 재실행해 조건에 맞는 선택·flag·엔딩을 반환한다. 별도의 분기 로직이나
플레이어 저장소를 만들지 않는다. 처음부터 읽기, 이전 선택으로 돌아가기, 경로/flag 확인을 제공한다.
원고를 수정하면 이전 미리보기의 선택을 막고 새 스냅샷으로 시작한다. saved/released 원장도 읽기 검수가 가능하다.

이미지는 검증된 scene_enter background만 표시하고 파일 hash를 다시 대조한다. 사운드·block 단위 연출,
네이티브 글꼴·접근성·기기 성능은 재현하지 않으므로 앱 검증을 대신하지 않는다.

## 제작실 백업 계약

`story-post-authoring` 형식 v1 JSON은 제작 테이블만 포함한다. 현재 미저장 문장·조건·연출도 포함하지만 실제 에셋 파일·Keychain 키·AI 설정은 포함하지 않는다. 5MB 제한, 테이블/열 이름과 문자열 검증, 작품·버전·언어 일치, 배포본 복원 거부를 적용한다. 서버 `/api/validate`로 분기·권리·해시를 검사한 뒤 확인창에서 승인하면 편집기에만 반영한다. 이후 명시적 저장이 필요하다. 검증 또는 확인 중 편집/작품 변경이 발생하면 복원을 버리고 현재 편집을 유지한다. 이는 여러 탭의 충돌 자동 병합 기능이 아니다.

## 작가용 폼

기본 폼은 한국어 명칭, 본문 형식·제작 상태·trigger/channel/action의 선택 목록을 제공한다. next_scene_id는 장면 제목과 안정 ID를 함께 표시하고 cue의 block/choice 대상은 같은 장면만, asset 대상은 같은 channel만 제공한다. channel/scene 변경으로 기존 연결이 유효하지 않게 되어도 자동으로 지우거나 다른 값으로 바꾸지 않는다. 오류 값을 별도 옵션으로 남기고 서버 검증에서 차단한다. 전체 테이블의 열 이름·저장 CSV는 기존 계약을 유지한다.

## 새 장면 생성 계약

기존 편지에 선택지를 추가해 새 letter/ending으로 가는 분기를 만든다. letter는 지정한 기존 장면으로 이어지는 한 선택을, ending은 고유 ending_id를 생성한다. stable scene ID에서 block/entry/continue ID를 파생하고 기존 ID 충돌·선택 8개·장면 200개·본문/문장 길이를 검사한다. 복사본 전체를 서버 검증해 순환과 도달 실패를 차단한 뒤 편집기에 교체하며 원장 저장은 별도다. 기존 선택·조건·효과·에셋·cue를 바꾸지 않는다. 검증 중 취소하거나 작품/원고가 바뀌면 응답을 적용하지 않는다. 새 작품 생성이나 원격 협업은 이 폼의 범위가 아니다.

## 장면 검색

장면 제목·ID·결말 ID·제작 메모와 본문/화자에서 로컬 문자열을 검색한다. NFKC·대소문자·공백을 정규화하되 정규식이나 외부 검색을 사용하지 않는다. 결과는 원장의 ordinal 순서를 유지한다. 검색만으로 선택한 장면이나 원장을 바꾸지 않으며 결과를 고르면 제목에 포커스를 이동한다. 새 작품/백업/장면 적용 시 필터를 초기화해 새 원고가 숨지 않게 한다.

## 구조 편집 보호와 1단계 취소

기본 폼의 block/choice/asset/cue 삭제는 원장 복사본에서 준비하고 확인·전체 서버 검증 뒤 적용한다. 마지막 본문/선택, cue가 참조하는 asset은 거부한다. block/choice를 삭제할 때 연결 cue·조건·효과를 함께 정리하고, 삭제한 선택에서만 쓰던 flag 정의는 남은 참조가 없을 때만 제거한다. 장면이나 다른 콘텐츠가 도달 불가가 되면 전체 검증이 삭제를 거부해 원장을 보존한다. 실제 에셋 파일은 삭제하지 않는다.

새 장면 생성·검증된 삭제·선택 규칙 적용은 직전 원장/검수 스냅샷 한 개를 보관한다. 동일 작품·편집 revision일 때만 되돌리고 이후 편집·새 로딩·검사 중에는 취소를 차단한다. 저장 뒤에도 다른 편집이 없으면 취소 후 다시 저장할 수 있다. 원격 revision은 되돌리지 않는다. 전체 테이블은 고급 직접 편집이며 이 자동 관계 정리/1단계 취소의 범위가 아니다.

장면 진입 배경은 앱과 제작실이 공통 해석기로 ordinal상 마지막 background cue를 사용한다.
hide/fade_out은 정적 배경을 비우며 다른 채널은 영향을 주지 않는다. 실제 시간 기반 fade,
이전 장면 배경 유지와 음향 재생은 현재 플레이 미리보기 범위 밖이다.

## 검수 시점의 원고 기록

검수 탭의 ‘현재 원고 검사’는 미저장 테이블 사본으로 `/api/validate`를 실행한다.
원장 SHA256·UTC 검수 시각·미저장 여부·제작표·분기와 테이블 사본을 보관하며 CSV를 저장하지 않는다.
검사 중 편집·작품 이동·새 불러오기가 발생하면 결과를 적용하지 않는다. 다음 편집 후 기존 결과는
‘이전 검수’로 표시하고 다시 검사하기 전에는 내보내기를 막는다.
`story-post-review` v1 JSON은 검수 기록이며 `story-post-authoring` 복원 백업과 구분한다.
실제 에셋 파일·AI 설정은 포함하지 않으며 내용 식별 hash는 서명이나 출시 승인이 아니다.
JSON 복사와 파일 링크를 제공하며 파일 다운로드 이벤트의 내장 브라우저 제한은 기존 백업과 같다.

## 선택 조건·효과 폼

원고의 각 선택지에서 ‘조건·효과 편집’을 열면 등록된 상태를 한국어 의미/안정 ID로 선택한다.
노출 조건은 모두 일치해야 선택지를 표시하고, 효과는 선택 확정 뒤 다음 장면 진입 전에 적용한다.
현재 엔진의 boolean equals/set만 지원하며 그룹당12개·중복 상태·미등록 상태·배포본을 보호한다.
다른 선택의 규칙·장면 연결·전역 상태 정의·에셋/연출은 보존한다. 새 상태 정의는 전체 테이블에서
관리한다. 전체 원장의 조건상 도달 검사 후에만 편집기에 적용하며 저장은 별도다.
취소/검사 중 원고 이동은 반영하지 않으며 적용한 규칙도 직전 구조 변경의1단계 취소를 지원한다.
v4 상태 설명에는 ‘소라와 동행 중’, ‘지도책을 선택함’, ‘연우의 개인 일기를 선택함’을 기록했다.

## 작업 버전 복제 보호

복제는 저장된 원본 revision이 일치해야 진행한다. UI는 수정 원고의 복제와 중복 제출을 막으며
요청 중에는 폼/닫기를 잠근다. 파일 작성은 임시 폴더에서 완료한 뒤 폴더·제작 manifest에 반영한다.
목록 게시 실패는 새 미등록 폴더를 정리해 재시도할 수 있고 기존 원본은 변경하지 않는다.
외부 목록 변경을 감지하면 보존하고 복제를 거부한다. 프로세스 강제 종료 뒤 자동 복구나
여러 서버 프로세스 간 파일 잠금/분산 트랜잭션은 제공하지 않는다.

## 오류 복구와 에셋 검수

CSV 헤더·작품 identity가 맞는 원고는 분기/에셋 오류를 함께 표시하며 편집기를 연다.
저장·검수·플레이 미리보기는 여전히 전체 검증을 통과해야 한다. 오류를 숨기거나 불변 배포본을
수정하지 않는다. 제작실의 ready/approved 시각 에셋은 파일/hash를 대조해 실제 이미지를 보여 주고
설명은 alt로 사용한다. 잘못된 hash/경로는 이미지 오류 안내로 바뀌며 저장 검사에서도 거부한다.
cue에 아직 연결하지 않은 ready 에셋도 파일·hash·권리 검사를 한다.

수동 planned 에셋의 초기 경로는 `assets/planned/<id>.png` 예약값이며 실제 파일은 만들지 않는다.
파일 준비 전에도 원장/cue 계획을 저장할 수 있지만 실행 패키지에서는 제외한다. 준비가 끝나면
실제 파일 위치·SHA-256·권리·종류에 맞는 확장자를 입력하고 ready로 바꾼다. 파일 업로드는 없다.
연출 종류/장면을 바꿔 폼을 갱신하면 같은 필드에 포커스를 복원하고 화면에 보이게 이동한다.

이미지의 ‘파일 해시 가져오기’는 `assets/` 안의20MB 이하 PNG·JPEG·WebP 파일을 읽고
경로/실제 형식·SHA-256을 확인한다. 파일을 바꾸거나 업로드하지 않는다. 성공 후 hash만 편집기에
반영하며 ready/권리 상태는 작가가 검토한다. 같으면 dirty를 만들지 않는다. 검사 중 원고/작품이
바뀌면 결과를 적용하지 않고 버튼에서 재시도할 수 있다. 오디오 해시 자동 확인은 범위 밖이다.

## 플레이 경로 기록

‘플레이 경로 내보내기’는 마지막 정상 미리보기의 선택 ID 순서·도착 장면·flag·선택 문장과
당시 원고 사본을 `story-post-playtest` v1 JSON으로 보관한다. 원장 revision과 UTC 미리보기
시각·당시 미저장 여부를 포함하며 실제 이미지/사운드·키·AI 설정은 포함하지 않는다.
현재 원고가 바뀌거나 새 원고 로딩/검사 중이면 내보내기를 막고 다시 시작해야 한다.
이전 선택으로 돌아간 뒤 내보내면 줄어든 실제 경로와 다시 계산한 상태를 기록한다.
게임의 진행 저장 파일이나 원고 복원 백업이 아니며 출시 승인도 아니다. JSON 복사/파일 링크를
제공한다. 미리보기는 공유 세션에서 늦은 성공/실패를 무시하고 기기 SQLite/CSV를 쓰지 않는다.

복제 성공 후 목록 읽기 실패는 작품 목록에 지속 안내한다. ‘작품 목록 다시 읽기’는 목록만
갱신해 기존 편집을 유지하며 복제를 다시 요청하지 않는다. 목록 요청 중 원고/로딩이 바뀌면
새 clone을 자동으로 열지 않는다. 실패 뒤 새로고침으로 미저장 원고를 버릴 필요가 없다.

원고 GET 실패도 대상 작품과 재시도 버튼을 목록에 남긴다. 성공한 복제의 목록 갱신과 원고 열기를
분리하므로 새 원고 GET 실패를 복제/목록 실패로 오인하지 않는다. ‘원고 다시 열기’는 GET만 수행하고
미저장 원고를 교체하기 전에 확인한다. 최신 불러오기만 오류를 표시하며 성공 뒤 안내를 해제한다.
